# git why: from a line of code to its intent

## Want
`git why <file>:<line>` blames the line, follows the commit's `Intent:`
trailer (or the merge that brought it in, the PR's other commits, or an
intent file the commit added), and prints the intent's id, status, PR,
supersede chain, Want, Not and Done when. On PATH as `git-why`, git runs it
as `git why`. The README opens with a 30-second install: the
`ao3575911/intent-first@v1` workflow, a first intent, and the git why install line.

## Not
No dependencies beyond Python 3 and git; `gh` is only an optional fallback
for squash merges whose trailer lives in the PR body. No stack traces: a
commit without an intent says so and shows the commit instead.

## Done when
- Trailer, merge, PR-commit, squash, supersede, rename, no-trailer and bad-input fixtures behave as specified
  check: `python3 scripts/test_git_why.py`
- In this repo, the 60s-window line of the rate limiter leads to its intent and the intent that superseded it
  check: `GIT_WHY_NO_GH=1 python3 bin/git-why src/ratelimit.py:21 | grep -q "Superseded by 20260928-rate-limit-login-per-account"`
- The selftest job runs the git why fixtures
- README starts with an install section using `@v1`
